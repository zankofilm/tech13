# مدرسه‌یار معلم — پروژه اندروید

> **نسخه 2.0.3-native-performance:** رابط اصلی Native است و مسیر شروع/ورود برای سرعت بهینه شده: تأخیر مصنوعی Splash حذف شده، Splash سیستمی Android استفاده می‌شود، ورود اثرانگشتی بدون لود کامل وب‌سایت به داشبورد Native برمی‌گردد و WebView احراز هویت سبک‌تر شده است. جزئیات در `RELEASE-NOTES-2.0.3-PERFORMANCE-FA.md` آمده است.

این پروژه یک اپلیکیشن اندرویدی برای پنل معلم مدرسه‌یار است. اپلیکیشن به سامانه واقعی روی هاست متصل می‌شود؛ بنابراین داده‌ها، مجوزها، کلاس‌ها، تکالیف، آزمون‌ها، حضور و غیاب، پیام‌ها، گزارش‌ها و سایر ماژول‌ها از همان بک‌اند و حساب کاربری فعلی استفاده می‌کنند و پایگاه داده جداگانه‌ای ساخته نمی‌شود.

## قابلیت‌های پیاده‌سازی‌شده

- رابط اصلی Native با Jetpack Compose / Material 3، پشتیبانی کامل RTL و طراحی فارسی.
- نگهداری پنل وب موجود در `WebPortalActivity` فقط به‌عنوان لایه سازگاری برای عملیات کامل ماژول‌هایی که هنوز API Native مستقل ندارند.
- محدودسازی ورود اپ به حساب دارای نقش `teacher`.
- ورود نخست با نام کاربری/کد ملی و رمز فعلی سامانه.
- پیشنهاد فعال‌سازی اثر انگشت پس از ورود موفق معلم.
- ذخیره نکردن رمز عبور؛ فقط نشست Bearer به‌صورت AES-GCM با کلید Android Keystore محافظت‌شده توسط زیست‌سنجی رمزنگاری می‌شود.
- بازیابی نشست بعدی فقط پس از تأیید زیست‌سنجی؛ در صورت انقضای نشست، ورود معمولی دوباره لازم است.
- دکمه «بروزرسانی» روی داشبورد معلم.
- همگام‌سازی Legacy دیگر با دستکاری سراسری تایمرهای سایت شتاب داده نمی‌شود؛ Sync سریع فقط باید روی APIهای مشخص Native پیاده‌سازی شود تا CPU، شبکه و سرور بی‌دلیل درگیر نشوند.
- انتخاب چند فایل برای بارگذاری، دانلود فایل‌های مستقیم، ذخیره خروجی‌های Blob تا ۴۰ مگابایت و ارسال صفحه به چاپ اندروید.
- بازکردن پیوندهای خارج از دامنه در مرورگر دستگاه و مسدودکردن HTTP و گواهی TLS نامعتبر.
- GitHub Actions برای ساخت APK قابل نصب.

## آدرس عملیاتی سامانه

این نسخه به‌صورت پیش‌فرض برای دامنه رسمی زیر تنظیم شده است:

`https://scooljavanrood.ir/app/`

اتصال HTTP، دامنه متفاوت در داخل WebView و گواهی TLS نامعتبر برای حفاظت از اطلاعات ورود مسدود می‌شوند. در صورت انتقال سامانه به دامنه دیگری، همچنان می‌توان `WEB_APP_URL` را در GitHub Actions یا Gradle override کرد.

## ساخت APK در GitHub

1. یک Repository جدید در GitHub بسازید.
2. تمام محتویات این پوشه را در شاخه `main` آن قرار دهید.
3. در GitHub وارد `Settings → Secrets and variables → Actions → Variables` شوید.
4. وارد زبانه `Actions` شوید.
5. گردش‌کار `Build Madreseyar Teacher APK` را انتخاب کنید و روی `Run workflow` بزنید. آدرس `https://scooljavanrood.ir/app/` از قبل به‌عنوان مقدار پیش‌فرض قرار داده شده است.
6. پس از پایان موفق اجرا، در بخش Artifacts فایل `Madreseyar-Teacher-APK` را دریافت کنید. داخل آن `app-debug.apk` قرار دارد.

این APK با کلید Debug امضاشده و برای نصب/آزمایش قابل استفاده است. برای انتشار عمومی در Google Play یا توزیع رسمی، باید کلید امضای Release اختصاصی بسازید و تنظیمات امضا را با GitHub Secrets اضافه کنید؛ کلید امضا را هرگز در Repository قرار ندهید.

## ساخت محلی با Gradle

نیازمندی‌ها: JDK 17، Android SDK Platform 35 و Gradle 8.9.

```bash
gradle --no-daemon :app:assembleDebug
```

خروجی:

`app/build/outputs/apk/debug/app-debug.apk`

## رفتار ورود با اثر انگشت

- اولین ورود با نام کاربری/رمز از فرم اصلی خود سامانه انجام می‌شود.
- پس از نمایش داشبورد معلم، اپلیکیشن فعال‌سازی اثر انگشت را پیشنهاد می‌کند.
- رمز عبور هرگز در اپلیکیشن ذخیره نمی‌شود.
- نشست سرور به‌صورت AES-GCM رمزنگاری می‌شود و کلید در Android Keystore با نیاز به زیست‌سنجی قوی ساخته می‌شود.
- خروج از حساب، انقضای نشست یا رد شدن نقش کاربر، نشست ذخیره‌شده اثر انگشتی را پاک می‌کند.
- اگر کاربر اثر انگشت را لغو کند، می‌تواند با رمز عبور وارد شود.

## بروزرسانی و اعلان‌ها

در نسخه 2.0.3 دستکاری عمومی `window.setInterval` حذف شده است. نسخه‌های قبل تایمرهای ۱۲ و ۱۵ ثانیه‌ای سایت را به ۵ ثانیه تبدیل می‌کردند که می‌توانست درخواست شبکه و پردازش را بیش از حد افزایش دهد. دکمه بروزرسانی دستی همچنان وجود دارد. Sync دوره‌ای سریع در رابط Native باید بعد از اتصال APIهای مشخص، فقط روی endpointهای موردنیاز و با lifecycle مناسب پیاده‌سازی شود.

اعلان Push سیستم‌عامل در زمانی که اپلیکیشن کاملاً بسته یا در پس‌زمینه متوقف است، به Firebase Cloud Messaging و تنظیم سمت سرور نیاز دارد و در این نسخه ادعای فعال بودن Push پس‌زمینه وجود ندارد.

## معماری و محدودیت‌ها

رابط اصلی برنامه با Compose Native ساخته شده است. `WebPortalActivity` فقط برای احراز هویت فعلی و عملیات Legacy ماژول‌هایی نگه داشته شده که هنوز API Native مستقل ندارند. ورود اولیه با نام کاربری/رمز همچنان برای تأیید حساب به وب‌اپ سرور وابسته است؛ ورود اثرانگشتی از نشست رمزنگاری‌شده محلی استفاده می‌کند و برای نمایش داشبورد Native منتظر رندر کامل سایت نمی‌ماند.

برای کارکرد کامل، هاست باید در دسترس اینترنت گوشی باشد و URL تنظیم‌شده به مسیر صحیح `/app/` اشاره کند.


## ممیزی کامل امکانات معلم

فایل `TEACHER-FEATURE-AUDIT-FA.md` تطبیق منوی قطعی، مسیرهای پنهان روزانه، افزونه‌ها، قابلیت‌های فایل/چاپ/دوربین و شکاف Push Notification را مستند می‌کند. نسخه 1.0.2 سازگاری `window.open()` برای چاپ/PDF و لینک خارجی، دوربین `capture=environment` و Preview فایل‌های Blob را نیز اضافه کرده است.

## Native 2.0.2 — No-Mix Login
در نسخه 2.0.2 جریان احراز هویت از نمایش داشبورد قدیمی جدا شده است. WebView در ورود فقط نقش broker احراز هویت را دارد و بعد از ثبت نشست معتبر معلم به رابط Native بازمی‌گردد. نسخه وب قدیمی فقط از بخش «بیشتر» به‌صورت صریح قابل بازکردن است.


## Native 2.0.3 — Performance
تأخیر ثابت ۱٫۱۵ ثانیه‌ای شروع حذف شده، System Splash جایگزین شده، Auth WebView تصاویر شبکه را در حالت پنهان دریافت نمی‌کند، Auto-login زودتر از اتمام کامل صفحه شروع می‌شود و ورود اثر انگشتی دیگر سایت را فقط برای نمایش داشبورد Native لود نمی‌کند.
